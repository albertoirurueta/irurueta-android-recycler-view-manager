== 1. Describe your data

First decide two things about your data model:

* what *identifies* an item, so the same item can be recognized in the old and the new list (usually an id); and
* what makes its *content* different, so the manager knows when an item that is still present must be rebound.

Here `id` identifies the item and `name` is its content. If an item keeps its `id` but its `name` changes, it is
reported as *updated*. If an `id` appears only in the new list it is *inserted*, if it appears only in the old list it
is *removed*, and if it changes position it is *moved*.

== 4. Notify changes

Each time the data changes, do these two steps in this order:

. Give the *new* list to the adapter, so `getItemCount()` already returns the new size.
. Call `notifyChanges(oldItems, newItems)`, passing the *old* list first.

[source,kotlin]
----
include::example$notifyChanges.kt[]
----

IMPORTANT: The argument order is `notifyChanges(oldItems, newItems)`. Swapping the lists, or updating the adapter
_after_ the call, makes `RecyclerView` see notifications that don't match the adapter's data. That leads to wrong
animations or an `IndexOutOfBoundsException` / "Inconsistency detected" crash.

Call `notifyChanges` on the main thread, like any other adapter notification. The detection runs synchronously on the
calling thread.

=== What is notified

[cols="1,2",options="header"]
|===
|Detected change |Adapter call

|Item only in the new list
|`notifyItemInserted(newPosition)`

|Item only in the old list
|`notifyItemRemoved(oldPosition)`

|Same item, different content
|`notifyItemChanged(position)`

|Same item, different position
|`notifyItemMoved(oldPosition, newPosition)`

|New list is empty (`adapter.itemCount == 0`)
|`notifyDataSetChanged()`
|===

Positions are sequential: each one refers to the list as it looks after the previous notifications have been applied,
which is how `RecyclerView` processes a series of notifications.

== Tips

* Keep the identity comparator stable. Comparing whole objects (`item1 == item2`) as the identity rule turns every
  edit into a removal plus an insertion instead of an update.
* Make the content comparator cheap. It is called for items that are present in both lists.
* Ids should be unique within a list. Duplicate identities make it ambiguous which item moved.
* The manager logs each notification at `DEBUG` level with the `RecyclerViewManager` tag, which helps when diagnosing
  unexpected animations (`adb logcat -s RecyclerViewManager`).
